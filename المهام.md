هذه الصفحة هي مرجع حالة العمل الحالي للـMVP فقط. لا تمنح أي وكيل صلاحية mutation أو certification؛ الـCI والـPR هما مصدر الإثبات.

## الحالة الحالية

- المسار التشغيلي الوحيد: `execution → main`.
- `main` هو مرجع الإنتاج، ولا تتم الكتابة المباشرة عليه.
- المرشح الحالي هو PR #1002؛ يجب دائمًا حل رأس `execution` الحي قبل اعتماد أي SHA.
- الـMVP التنفيذي المقفل هو عشر قدرات Browser-Local: ست صور وأربعة فيديو.
- Runtime authority الحالي محصور في `src/config/registry.ts` و`src/lib/execution/canonical-executor.ts` وعقود المخرجات وverifiers.
- بوابة الاختبار الحالية هي `npm test` مع اختبارات MVP المتخصصة للـregistry وscope وcorpus وexecutor وpersistence وRed Team.
- لا توجد حزمة Runtime حالية في `apps/agent-editor` أو `src/lib/agent/` السابقة؛ مسارات الاسترداد التاريخية موثقة منفصلًا.
- الحالة النهائية الحالية: `NOT READY` حتى إغلاق بوابة الحوكمة وإتمام Prompt 19/20.

قواعد التشغيل:
- لا ينتظر أي وكيل وكيلًا آخر.
- لا توجد مهام مشتركة الملكية أو handoff.
- لكل ملف مالك أساسي واحد.
- أي عيب تقني واضح يعالج مباشرة ضمن الصلاحيات، دون انتظار موافقة وكيل آخر.
- `execution` هو canonical integration lane، لكن فروع العمل المؤقتة/المعزولة (`agent/*`, `task/*`, `fix/*`, `feature/*`, `stage/*`, `redteam/*` وغيرها) مسموحة للعزل والتوازي والتجارب دون اشتراط PR إلى `execution`.
- أي تعاون أو نشر متزامن يستخدم mutation mechanism غير قسري وrace-safe/CAS؛ moving head يعني reconciliation وإعادة التأهيل، وليس overwrite.
- يعتمد كل وكيل على repository state والـcontracts، وليس على تقارير الوكلاء.
- تغير `execution` يبطل أي evidence خاص بالـSHA السابق؛ يعاد القراءة وتوليد الأدلة على الـSHA الجديد.
- task closure = IMPLEMENTED → TARGETED TEST → REGRESSION → VERIFIED → EVIDENCE → CLOSED؛ handoff والجلسة البديلة اختياريان فقط عند وجود حاجة فعلية.
- 100/100 يظل ممنوعًا قبل اكتمال جميع release gates على exact-SHA واحد.


### V3 — لا Centralized Claim
في نمط V3 لا توجد آلية CLAIM/LEASE مركزية مطلوبة لبدء العمل. ملكية المهام ثابتة حسب الـlane، والوكيل المكلّف يعمل فورًا على نطاقه. سجلات claim/heartbeat التاريخية لا تفرض تنسيقًا جديدًا، ولا يجوز استخدام غياب claim أو رد وكيل آخر كسبب للتوقف.

## Governance synchronization state

- `AGENTS.md` و`docs/ARCHITECTURE_LOCK.md` هما عقد صلاحيات التنفيذ الداخلية.
- GitHub Ruleset `FLIXO-MAIN-PROTECTION` هو المرجع الحي للحماية الخارجية.
- `verify-main-ruleset.mjs` لا يغيّر الحوكمة؛ إنه يكتشف ويغلق المسار عند عدم التطابق.
- لذلك لا يجوز مواءمة الحالة عبر تخفيف verifier. الإصلاح الصحيح للـlive mismatch يجب أن يتم في GitHub Administration ثم إعادة التحقق على exact SHA.

## Governance blocker

Ruleset `FLIXO-MAIN-PROTECTION` (ID 23854302) is active for `main`, but the live policy is weaker than the active plan requires:

- approving reviews = 0 (required 1)
- stale reviews dismissed on push = false (required true)
- Code Owner review = false (required true)
- latest push approval = false (required true)
- review-thread resolution = false (required true)
- strict required checks = false (required true)

PR #1002 also has no independent human approving review. Automated security comments are not equivalent to a human approval.

## Evidence rule

Any mutation on `execution` changes the candidate SHA and invalidates prior SHA-specific certification evidence. No stale or skipped evidence may be used to certify the release.

Historical recovery and certification records remain available under `docs/` but are not current runtime authority.
