Admission gates

ADMISSION = REJECT

## 7. NATIVE OPPOSITION

The task primitive is:

ONE TASK

ONE SOLVER
+
ONE OPPONENT

Backups are recovery roles, not additional simultaneous primaries.

Solver contract

construct the solution;
perform the admitted work;
produce claims and evidence;
answer challenges;
never certify;
never arbitrate its own dispute.

Opponent contract

construct falsification challenges;
search for counterexamples;
identify evidence that would disprove success;
establish an independent challenge position first;
consume controlled Solver output only after the independent-start boundary;
never certify;
never become the sole source of final truth.

## 9. OPPOSITION PLAN — TARGET

No CELL admission without:
attackSurface
falsificationQuestions
expectedCounterexamples
evidenceThatWouldDisproveSuccess
independenceRequirement
opponentRecoveryPlan

Definitions:

attackSurface: where the solution is most exposed to failure.
falsificationQuestions: questions capable of disproving the claim or acceptance.
expectedCounterexamples: known/generated cases expected to fail if the claim is wrong.
evidenceThatWouldDisproveSuccess: observable proof that forces reject/rework/escalate.
independenceRequirement: minimum separation of identities/context/evidence/execution assumptions.
opponentRecoveryPlan: bounded recovery for unavailable/stuck/invalid Opponent output.
escalationPolicy: deterministic conditions for replan/escalate/dispute.

Arbitration is a function of the existing Control Plane/Governance path, not a new authority seat.

Required envelope

~~~
claim:
  claimId: string
  authorId: string
  statement: string
  evidenceIds: []

counterclaim:
  counterclaimId: string
  authorId: string
  statement: string
  evidenceIds: []

arbitration:
  authority: existingControlPlaneOrGovernanceGate
  ruleSetVersion: string
  requiredEvidence: []
  independenceCheck: string
  decisionBasis: string

disposition:
  state: RESOLVED | MORE_EVIDENCE | REPLAN | ESCALATE | DISPUTED
  rationale: string
  evidenceIds: []
  nextAction: string
~~~

State meaning

RESOLVED: evidence materially resolves the dispute.
MORE_EVIDENCE: evidence is insufficient or ambiguous.
REPLAN: assumptions/criteria/route must change through canonical planning.
ESCALATE: policy requires authorized escalation.
DISPUTED: material conflict remains without a valid deterministic close.

Hard boundary: Solver cannot resolve its own disputed claim. Opponent cannot turn its own rejection into certification.
