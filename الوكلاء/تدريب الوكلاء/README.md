# برنامج تدريب جميع الوكلاء — FLIXO

هذا البرنامج هو معيار رفع الكفاءة الوظيفية للوكلاء، وليس تدريب نماذج الذكاء الاصطناعي ذاتيًا.

## هدف 100/100

لا يُمنح الوكيل تقييم 100/100 لمجرد وجود ملف تعريف. يحصل على 100/100 عندما:
1. يكون نطاقه واختصاصه واضحين وغير متضاربين.
2. يملك منهج عمل قابلًا للتنفيذ.
3. يثبت الهوية الدقيقة للـSHA والمرجع.
4. يملك أدلة قابلة للمراجعة لكل ادعاء مهم.
5. يفشل مغلقًا عند نقص البيانات أو تضارب الهوية.
6. يحافظ على حدود الأمن والخصوصية.
7. يتعامل مع الحالات السلبية والخصم/Red Team، بحسب دوره.
8. يسلم مخرجات منظمة للوكلاء اللاحقين.
9. يمر بعقد الاختبارات الخاص بدوره.
10. لا يدعي PASS/GREEN/CERTIFIED دون سلطة الشهادة.

## سلم الكفاءة

- 0–59: غير مؤهل.
- 60–74: يعمل مع قيود.
- 75–89: قوي.
- 90–99: متقدم ويحتاج فجوة محددة.
- 100: مكتمل وفق عقد الدور وقابل للإثبات.

## الوكلاء المدربون رسميًا

المستكشف AI، المستكشف 2، المطور AI، i18n Agent، Maintainer Agent، QA Agent، Red Team 1، Red Team 2.

لكل وكيل تعريف رسمي، نطاق كتابة مستقل، وبوابات دورية قابلة للاختبار.

## الأدوار

- المستكشف AI: معرفة FLIXO الداخلية.
- المستكشف 2: التفنيد والاعتراض على نتائج المستكشف.
- المطور AI: مقارنة FLIXO خارجيًا وتحويل الفجوات إلى فرص تطوير.
- i18n Agent: صحة وتغطية التعريب والـRTL/SEO.
- Maintainer Agent: سلامة البنية والتكامل والعقود.
- QA Agent: الاختبار والتحقق والأدلة.
- Red Team 1: اختبار هجومي أمني مستقل.
- Red Team 2: هجوم مضاد/تفنيد هجومي مستقل.

لكل دور عقد خاص واختبارات خاصة. لا يوجد وكيل يقرر لنفسه أنه 100/100.

## دورة الوصول إلى 100

إذا فشل الوكيل في أي تمرين، لا نرفع الدرجة يدويًا. يولد النظام remediation محددًا، ثم يعاد الامتحان على SHA جديد. يثبت الدرس فقط بعد مراجعة مستقلة ونجاحين واختبار ارتداد.

## اختبارات القدرات الفعلية للدور

يوجد امتحان آلي مستقل لكل وكيل رسمي في `scripts/agent-learning/run-role-drills.mjs` مع حالات موجبة وسلبية.

| الوكيل | الامتحان |
|---|---|
| المستكشف AI | تغطية المستودع، الاعتماديات، والتغير الدلالي |
| المستكشف 2 | تفنيد الادعاء وتوليد بديل |
| المطور AI | مقارنة خارجية مع SHA مرجعي وترتيب فجوات |
| FLIXO i18n Agent | اكتمال اللغات وRTL/LTR وSEO |
| FLIXO Repository Maintainer Agent | السلطات والتعارضات والانجراف |
| FLIXO QA Agent | أوامر التحقق ورفض الدليل القديم |
| Red Team 1 | فرضية هجوم وإعادة إنتاج آمنة |
| Red Team 2 | حالة مضادة وتفنيد نتيجة هجومية |

يُقبل امتحان الدور فقط عندما ينجح السيناريو الصحيح ويرفض السيناريو المضاد. ثم يبقى `Behavioral Evidence` منفصلًا حتى توجد تجربة تشغيل حقيقية للوكيل نفسه.

## التدريب التصاعدي

المستوى 1: قراءة القاعدة والعقد.
المستوى 2: حل المهمة الصحيحة.
المستوى 3: رفض الحالة المضادة.
المستوى 4: تفسير النتيجة بالأدلة.
المستوى 5: إعادة النجاح بعد تغيير SHA أو السياق.
المستوى 6: تحويل الفشل إلى درس واختبار ارتداد.

لا ينتقل الوكيل للمستوى التالي بسبب الوصف النظري فقط؛ الانتقال مرتبط بنتيجة الامتحان.
## بروتوكول العلاج الذكي

عند فشل تمرين، يسجل النظام: `failed_gate` → `root_cause` → `remediation` → `retest`.
إذا تكرر نفس الفشل مرتين، يجب ترقية الحالة من مجرد إعادة المحاولة إلى إنشاء Regression Test جديد قبل اعتبار المهمة مستقرة.
إذا اختلفت النتيجة بين وكيلين، تحفظ النتيجتان ولا يتم إلغاء إحداهما بالتصويت؛ يلزم دليل تفنيد مستقل.
