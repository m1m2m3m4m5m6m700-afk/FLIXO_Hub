# GitHub Repository Metadata Setup

This document records repository-level settings that are useful for developer discovery but are not stored in the Git tree.

## Repository description

Use:

> Open-source browser-first AI toolbox and governed developer platform for privacy-preserving local workflows, deterministic file processing, and autonomous multi-agent development control.

## Topics

Use the smallest accurate topic set that matches the project:

`ai`, `ai-agents`, `autonomous-agents`, `multi-agent-systems`, `agent-orchestration`, `developer-tools`, `developer-platform`, `local-first`, `privacy`, `browser-automation`, `deterministic-execution`, `typescript`, `react`, `vite`, `cloudflare-workers`, `workflow-automation`, `software-governance`.

Do not add unrelated high-volume keywords merely to increase search exposure.

## Discussions

Enable GitHub Discussions for the repository and create these initial categories:

- Q&A
- Ideas
- Architecture
- Show and tell
- Announcements
- Community

Pin a welcome discussion that links to the README, CONTRIBUTING, SUPPORT, SECURITY, and Contribution Contract.

## Social preview

Configure a repository social preview that visually communicates FLIXO Hub's name, browser-first AI/developer-platform positioning, privacy/local-processing boundary, and governed multi-agent execution model. Keep text sparse enough to remain legible at small sizes.

## Security settings

For a public repository, verify the GitHub security and analysis settings independently of repository code:

- Dependabot alerts enabled.
- Dependabot security updates enabled where supported.
- Secret scanning and push protection enabled where supported.
- Code scanning/CodeQL enabled.
- Private vulnerability reporting enabled where supported.

These settings are administrative controls. The repository workflows and documents must not claim them as enabled until the live GitHub settings are verified.

## Verification

After changing external settings, visit the repository's **Insights → Community Standards** and verify the community checklist. GitHub documents that page as the maintainer-facing checklist for public repository health.

Record the verification date and any limitations in the repository's project-health evidence. Do not store credentials or sensitive administrative responses in the repository.
