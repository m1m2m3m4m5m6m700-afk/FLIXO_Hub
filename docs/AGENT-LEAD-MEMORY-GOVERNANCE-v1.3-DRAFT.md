# FLIXO_Hub — نظام ذاكرة الوكيل القائد

**الإصدار:** 1.3 — مسودة بانتظار اعتماد المالك  
**يحل محل:** 1.2  
**الحالة:** BOOTSTRAP / اقتراح وتوثيق فقط

## سجل التغييرات عن 1.2

1. استثناء صريح للمهمة EXEC-LEAD-MEMORY-001 من شرط مزامنة الذاكرة العام أثناء تأسيس الملفات الثلاثة.
2. معيار إغلاق مستقل للمهمة: الملفات الثلاثة مدموجة، دليل التحقق مرفق، واعتماد المالك موثق وقابل للتحقق.
3. اعتماد المالك لا يثبت بنص داخل ملفات الذاكرة أو وصف PR؛ يلزم GitHub metadata قابل للتحقق.
4. لا يطبق التقليص التلقائي إلا بعد 10 PRs مكتملة على الأقل ضمن نافذة القياس.
5. حجب الأداة أو الفحص يبلغ عبر Issue موسومة agent-blocked.
6. انتقال BOOTSTRAP إلى ACTIVE لا يحدث بالاستنتاج ولا بمجرد كتابة الوكيل للحالة.

## 1. بنية الذاكرة

Core هي هذه الوثيقة والقواعد المعمارية الثابتة والإرشادات المعتمدة من المالك. Persistent هي STATE.md وDECISIONS.md وMEMORY.md. Working هو سياق الجلسة.

ملفات Persistent تُعدّل عبر PR على فرع agent/*، ويملكها المالك في CODEOWNERS. كل حقيقة فيها يجب أن تحمل مصدرها: commit أو مخرج تشغيل أو قرار مالك. المستودع عام، ولذلك لا أسرار ولا بيانات شخصية ولا تفاصيل ثغرات غير مُصلحة.

## 2. Bootstrap

حتى وجود الملفات الثلاثة على الفرع المعتمد ودمجها بموافقة المالك، يعمل الوكيل في وضع اقتراح وتوثيق فقط.

**استثناء صريح:** EXEC-LEAD-MEMORY-001 مستثناة من شرط مزامنة الذاكرة العام في Definition of Done أثناء تأسيس الذاكرة، منعاً للدوران المنطقي.

**معيار إغلاق EXEC-LEAD-MEMORY-001:**
- وجود STATE.md وDECISIONS.md وMEMORY.md.
- كل الحقائق مثبتة ومصادرها مذكورة.
- وجود قسم «ما لم يُتحقق منه».
- إرفاق دليل تحقق فعلي في PR.
- دمج الملفات في الفرع المعتمد.
- تسجيل اعتماد المالك وفق القسم 4.

لا تصبح ACTIVE إلا بعد تحقق جميع الشروط. الذاكرة لا تستطيع وحدها إثبات انتقال السلطة.

إذا حجبت أداة كتابة أو فحص أمني، يتوقف الوكيل ويبلغ عبر Issue تحمل label agent-blocked، مع المهمة والأداة والسبب والعملية المتوقفة والقرار المطلوب. لا يوجد التفاف أو تجزئة لتجاوز الحجب.

## 3. Definition of Done العادي

للمهام العادية: نجاح الاختبارات وlint وtype-check وbuild، اختبار إصلاح، دليل فعلي، نطاق مبرر، فحص العقود المعمارية، فحوص الأمان، rollback عند الحاجة، مراجعة مستقلة، ومزامنة الذاكرة. الاستثناء الوحيد أثناء Bootstrap هو EXEC-LEAD-MEMORY-001 كما ورد أعلاه.

## 4. الاعتماد

لا تصبح الوثيقة نافذة إلا باعتماد المالك. إثبات الاعتماد يجب أن يكون قابلاً للتحقق من GitHub metadata. المقبول: موافقة PR من حساب المالك المدرج في CODEOWNERS، أو commit موقّع يمكن ربطه بحساب المالك. النص الموجود داخل STATE.md أو DECISIONS.md أو MEMORY.md أو وصف PR ليس دليلاً مستقلاً على الاعتماد.

## 5. تقليص الصلاحية

تقاس آخر 20 PR أو آخر 30 يوماً، أيهما أقل. العتبات: نجاح البناء أقل من 90%، regressions أكثر من 2، rollback أكثر من 10%، أو رفض المراجعين أكثر من 30%.

لا يطبق التقليص التلقائي قبل وجود 10 PRs مكتملة على الأقل في نافذة القياس. بعد بلوغ الحد، تجاوز أي عتبة يقيد الوكيل إلى «اقتراح وتوثيق فقط». لا يرفع القيد إلا المالك.
