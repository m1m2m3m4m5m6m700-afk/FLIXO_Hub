# Support

Use the repository's public contribution surfaces so questions, defects, and proposals stay visible and actionable.

## Where to ask for help

- **Usage or setup question:** check the README and relevant documentation first. When GitHub Discussions is enabled, use the Q&A category for questions that do not describe a concrete code defect.
- **Reproducible bug:** open the **Bug report** issue form and include the smallest reliable reproduction.
- **Feature or product idea:** open the **Feature request** form and describe the user or developer problem before proposing implementation.
- **Reusable contribution:** use the **Contribution** issue form and the Developer Contribution Center.
- **Security vulnerability:** follow [SECURITY.md](SECURITY.md). Do not publish exploitable details, credentials, or sensitive data in a public issue.
- **Accessibility barrier:** follow [ACCESSIBILITY.md](ACCESSIBILITY.md) and include the affected route or component plus a reproducible description.

Before opening a new issue, search existing issues and avoid duplicate reports. Include the affected version or exact commit SHA when the behavior is version-sensitive.
